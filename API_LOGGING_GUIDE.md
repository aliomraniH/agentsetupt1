# API Logging and Tracking System

## Overview

This document describes the comprehensive API logging and tracking system that provides deep visibility into:
- **Request Sources**: Which applications/clients are making requests
- **API Call Chains**: Complete sequence of external API calls
- **Claude AI Usage**: Whether clients use embedded Claude or their own AI
- **Performance Metrics**: Response times, success rates, and bottlenecks

## Problem Statement

Previously, it was unclear:
1. Which third-party applications were calling our APIs
2. Whether they used our embedded Claude responses or their own AI agents
3. The sequence of external API calls (Alpha Vantage, Perplexity, etc.)
4. How stock price requests were being handled by different sources

## Request Source Tracking

### Source Types

The system automatically identifies request sources:

| Source Type | Detection Method | Example Use Case |
|-------------|------------------|------------------|
| `web_app` | User-Agent contains browser identifiers | Web browser access |
| `mobile_app` | User-Agent contains Android/iOS | Mobile application |
| `third_party` | Custom X-Client-ID header or known user-agent | stock-report app |
| `embedded_ai` | `/embedded-ai/` endpoints or X-Client-ID | Apps using our Claude |
| `external_api` | API client user-agents (curl, httpx) | API automation |
| `unknown` | Cannot determine from headers | Unidentified clients |

### Identification Headers

Clients can identify themselves using:
- `X-Client-ID`: Unique identifier for the application (e.g., "stock-report")
- `X-Source-Type`: Explicit source type (e.g., "third_party")
- `User-Agent`: Standard HTTP user agent string

Example:
```bash
curl -X POST http://api.example.com/api/v1/agents/stock-monitor/run \
  -H "X-Client-ID: stock-report" \
  -H "X-Source-Type: third_party" \
  -H "Content-Type: application/json"
```

## External API Call Tracking

Every call to external APIs is logged with:
- API name (Alpha Vantage, Perplexity, Anthropic, etc.)
- Endpoint/operation
- Duration in milliseconds
- Success/failure status
- HTTP status code
- Response size

### Example API Call Chain

For a stock price request, you might see:
```
1. Request: GET /api/v1/agents/stock-monitor/quick
   Source: third_party (stock-report)

   External API Calls:
   ├─ Alpha Vantage: /query?symbol=AAPL [120ms] ✓

   ├─ Alpha Vantage: /query?symbol=MSFT [failed]
   └─ Perplexity: /chat/completions (MSFT) [890ms] ✓

   Total Duration: 1,245ms
   Status: 200 OK
```

## Claude AI Usage Tracking

### Usage Types

| Usage Type | Description | When Used |
|------------|-------------|-----------|
| `embedded` | Client uses our Claude responses | `/embedded-ai/` endpoints |
| `external` | Client has their own AI | Standard endpoints, no Claude call |
| `passthrough` | Request forwarded to Claude | Direct Claude agent calls |
| `not_applicable` | No AI involved | Health checks, data-only endpoints |

### How It Works

**Embedded AI Usage** (Stock-Report using our Claude):
```javascript
// stock-report calls embedded AI endpoint
fetch('https://api.example.com/api/v1/embedded-ai/stocks/query', {
  method: 'POST',
  headers: { 'X-Client-ID': 'stock-report' },
  body: JSON.stringify({
    symbols: ['AAPL', 'GOOGL'],
    include_ai_summary: true
  })
})

// Response includes AI summary generated by our Claude
// Logged as: claude_usage_type = "embedded"
```

**External AI Usage** (Stock-Report using their own AI):
```javascript
// stock-report gets raw data
fetch('https://api.example.com/api/v1/agents/stock-monitor/run', {
  method: 'POST',
  headers: { 'X-Client-ID': 'stock-report' }
})

// Then they call their own LLM for analysis
// Logged as: claude_usage_type = "not_applicable" or "external"
```

### Use Case 2: Understanding Stock Price Request Flow

**Scenario**: A client requests stock prices. What happens?

**Flow**:
1. Request arrives → logged with source info
2. Stock Monitor Agent tries Alpha Vantage → logged
3. If Alpha Vantage fails → Perplexity fallback → logged
4. Response sent → duration and success recorded

**View the flow**:
```bash
curl http://api.example.com/api/v1/logging/api-sequences?last_n=10
```

## Implementation Details

### RequestContext

Each request creates a `RequestContext` object that tracks:
- Request metadata (method, path, headers)
- Source information
- API call type
- External API calls made
- Claude usage
- Timing and performance
- Sequence number

### API Logger

Global `api_logger` instance provides:
- `create_request_context()`: Initialize tracking for a request
- `log_external_api_call()`: Track calls to external APIs
- `log_claude_usage()`: Track Claude AI usage
- `complete_request()`: Finalize request tracking
- `get_request_stats()`: Get statistics
- `get_recent_requests()`: Get request logs

## Best Practices

### For API Providers (You)

1. **Always identify external API calls**
   ```python
   api_call = api_logger.log_external_api_call("Alpha Vantage", endpoint, "GET")
   # ... make call ...
   api_call.complete(success=True, status_code=200)
   ```

2. **Log Claude usage appropriately**
   ```python
   api_logger.log_claude_usage(
       usage_type=ClaudeUsageType.EMBEDDED,
       model=model_name,
       tokens=token_count
   )
   ```

3. **Use sequence numbers for tracing**
   - Automatic via middleware
   - Helps trace requests through the system

### For API Consumers (Third Parties)

1. **Identify your application**
   ```
   X-Client-ID: your-app-name
   ```

2. **Use embedded AI endpoints when possible**
   - Simpler implementation
   - No need to manage your own LLM
   - Optimized prompts

3. **Check usage statistics**
   - Monitor your API consumption
   - Optimize request patterns
